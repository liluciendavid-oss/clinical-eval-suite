# Error Taxonomy v1.1｜肝胆介入垂类的大模型错误分类学

**用途**：把"这个回答不好"翻译成**可计数、可定位、可自动检测**的错误类型，从而支撑 JD 职责①「定位模型短板，为版本迭代提供清晰、可解释的依据」。
**最后更新**：2026-10-07

**v1.0 → v1.1 变更**（由规则层实现驱动，非由清单外观察驱动）：

1. 新增 **§1.1 `detection_hint` 的极性**——发现该字段承载两种相反语义，原 E2a 定义会把"必须拒绝治疗"类题目的**正确答案**判成漏掉 critical 红旗。题库 70 条红旗全部补 `hint_polarity` 标注。
2. 新增错误码 **E2d 红旗被违反**（forbid 型断言出现），补上 E2a/E2b 只覆盖"不作为"、不覆盖"乱作为"的结构性缺口。E2d 一律 `flag_for_review`。
3. 新增 **§2.6 疾病科普段落线索句库**、**§2.8 规则层辅助词典**（守卫与可观测代理）——此前规则层实现所需的词典无处存放，只能硬编码，违反"可 review"原则。
4. 新增 **§5 阳性对照验收门**，明确 recall 必须与"零缺陷对照上 confirmed = 0"同时验收，并规定无阳性对照的错误码必须显式列出。
5. `error_instances.jsonl` 增加 `span_kind`（区分 `match` / `omission`）与 `rule_version` 字段。

## 0. 设计原则

### 原则 1：三层分工，精度递减、召回递增

没有任何单一方法能既准又全。硬把语义判断塞进正则会产生大量误报，硬让人工读完 130 份回答会破产。所以：

| 层 | 精度 | 召回 | 负责 | 输出 |
|---|---|---|---|---|
| **规则层** `rule_check.py` | 高 | 低 | 有确定文本特征的错误 | `confirmed`（可直接采信）或 `flag_for_review`（必须人工裁定） |
| **LLM-judge 层** | 中 | 中 | 需要语义理解的错误 | 结构化 JSON + **必须引用原文片段作为证据** |
| **人工层** | 金标准 | 全 | 全部，并仲裁前两层的 flag | 分数 + 错误实例清单 + 清单外观察 |

> **`confirmed` 与 `flag_for_review` 的界线是本文件最重要的约定**：只有当规则的假阳性率在直觉上接近 0 时才允许 `confirmed`。举例——"回答里出现 `NCT12345678` 而白名单里没有"只能是 `flag`，因为白名单不可能穷尽真实试验；而"活度写成 150 GBq"可以 `confirmed`，因为 Y90 单次活度的物理上限远低于此。

### 原则 2：一个错误实例只能归一类

多标签会让"错误总数"无法解释（同一句话被计三次，模型间比较就被词典覆盖率而非真实质量决定）。**就高不就低**：既符合 E1a（数值错）又符合 E2a（漏红旗）时，归 E1a，因为数值错是更根本的失效。

**E1a 与 E9 的分界（v1.1 明确）**：一个数值可能同时"落在公认区间之外"（E1a）与"超出物理可能区间"（E9）。归码规则按**荒谬程度**而非按发现顺序：

| 情形 | 归码 | verdict | 例子 |
|---|---|---|---|
| 超出 §2.5 的物理可能区间 / 荒谬判错线 | **E9** | confirmed | 处方活度 150 GBq（上限 10 GBq） |
| 物理上可能，但不在权威取值集合或公认口径内 | **E1a** | flag_for_review | 换算常数写 47.5（权威为 49.38 / 49.67 / 50） |

> 这条分界是实测逼出来的：缺陷注入器原先把文中第一个剂量数字乘以 27，自以为在注入 E1a，实际注入的全是 E9——于是 E1a 的严格 recall 恒为 0，只靠"归码等价"蒙混过关。**一个只能靠等价映射才算检出的阳性对照，等于没有阳性对照。** 现已拆成两个注入器：`inj_E9_magnitude` 专管荒谬值，`inj_E1a_number` 专管"错得看起来很专业"的阈值。自检同时报严格 recall 与归码等价 recall，两者不一致时必须能解释原因。

### 原则 3：taxonomy 必须能长大

题库作者想到的错误类型一定不全。所以 rubric §1 第 8 步强制每份回答填 1 条 `off_list_observation`。这些观察在阶段 3 回收，归并后作为 `E11+` 追加，并记录版本。**一个从不更新的 taxonomy 说明它没在被真正使用。**

|---|---|---|---|---|

| **E2b** | 遗漏非 critical 红旗 | `severity∈{high,moderate}` 且 `hint_polarity=mention` 的命中率 < 1（`mixed` 型降为 flag） | 规则 confirmed | D3 |

> **E12 是本项目专门加的一类**，通用医学评测里常被忽略。它是"幻觉"在临床场景里最危险的形态：模型编造一个"该患者肌酐 210 μmol/L"，然后据此给出一个逻辑自洽但完全错误的禁忌判断——推理链看起来完美，D2 挑不出毛病，只有与 vignette 逐字段比对才能抓到。检测方式：抽取回答中所有 `(实体, 数值, 单位)` 三元组，与 `vignette` 的结构化字段做集合比对，出现 vignette 中不存在的实体-数值对即 confirmed。

### 1.1 `detection_hint` 的极性：一个把 E2a 判反的坑（v1.1 新增）

`detection_hint` 原本被当成单一语义使用：「hint 全部不出现 ⇒ 该红旗被漏掉 ⇒ E2a confirmed」。实现规则层时逐条核对 70 条红旗发现，**同一个字段承载了两种相反的含义**：

| 类型 | 例子 | hint 的语义 | hint 全不出现意味着 |
|---|---|---|---|
| **mention** | SIRT-001 RF2「未把腹水、肝性脑病、胆红素升高识别为失代偿标志」→ `腹水/脑病/胆红素/失代偿/Child-Pugh` | 必须提及的安全项 | **漏掉了** → E2a 成立 |
| **forbid** | SIRT-001 RF1「给出 Y90 可行、可以尝试或建议实施的结论」→ `可行/可以/建议行/推荐 Y90/适合 Y90/予以 Y90` | 说出来就算犯错的断言 | **恰恰是正确答案** → E2a 反向误报 |

按原定义跑规则层，SIRT-001 这类"必须拒绝治疗"的题上，**答对的文件会被判成漏掉 critical 红旗**——而这正是整套评测里安全权重最高的一类题。误报方向与评测目的完全相反。

**处置**：`red_flags` 增加必填标注字段 `hint_polarity ∈ {mention, forbid, mixed}`，70 条红旗已于 2026-10-07 全部标注（**mention 53 / mixed 16 / forbid 1**，逐条清单与判定理由见 `docs/_hint_polarity_review.md`）。规则层据此分流：

| 极性 | hint 全不出现 | hint 出现且未被否定 |
|---|---|---|
| `mention` | E2a / E2b **confirmed** | 无 finding（是否真的正确处置由人工判 hit/partial） |
| `forbid` | 无 finding | **E2d flag_for_review** |
| `mixed` | E2a / E2b **降为 flag** | 无 finding（无法判断命中的是禁句还是主题词） |

**为什么 E2d 只能是 flag**：否定可以出现在任意远处。「本例不适合 Y90」里的「适合 Y90」是正确答案；「必须优先排除的安全项：给出 Y90 可行的结论」是在**列举**要排除的错误。规则层用两道守卫（`近距否定前缀` + `禁止性框架`，见 §2.8.2）挡掉绝大多数，但"引用一个错误结论以便驳斥它"的句式无法用正则穷尽，按 §0 原则 1 只能停在 flag。

> **这条是本文件最重要的一次修订**，因为它说明一件事：`detection_hint` 这种"看起来只是给规则层用的辅助字段"，一旦语义有歧义，产出的就不是噪声而是**方向性错误**——它会把最该报警的正确答案判成最严重的失效。schema 层面把极性显式化（`schema.py` 对未标注的红旗报 WARN），比在规则层里猜要可靠得多。

> **纯 `forbid` 型红旗只有 1 条（SIRT-001 RF1），这是标注纪律的结果而非疏忽。** 初版曾把 8 条标成 `forbid`，复核时发现其中 7 条的 hint 表混有中性主题词——`OS`/`生存`/`国际`/`全球`/`随机`/`标准剂量`/`安全`/`放弃`——正确答案同样会用到它们，于是"缺席即漏报"与"出现即违规"两个方向都不成立，全部降级为 `mixed`。
>
> **直接后果必须写明**：E2d 的阳性对照因此极薄（只有 1 道题可注入）。要把 E2d 做成可靠的检测，得把标注粒度从"红旗级"降到"hint 级"（同一条红旗里区分主题词与禁句），那是 schema v1.2 的工作。在此之前，**E2d 的 recall 数字不具备解释力，只能作为存在性证明**。

## 2. 检测词典与白名单

> 词典是规则层的全部智能所在。它们必须**可版本化、可 review、可扩充**，因此单独成节而不是硬编码在代码里。`src/rule_check.py` 从本文件的 §2.x 表格读取（实际实现为 `src/dictionaries.py`，与本文件保持同步，改一处必须改另一处）。

### 2.1 术语混淆词典（E1b）

成对出现即判错。左列为正确术语在该语境下应有的含义，右列为常被混淆的对象。

| 正确术语 | 常被混淆为 | 为什么混淆是错的 |
|---|---|---|
| mRECIST | RECIST 1.1 | Y90 后肿瘤坏死但体积不变，RECIST 1.1 只测径线会系统性低估反应 |
| LI-RADS Treatment Response (LR-TR) | LI-RADS 诊断分类 | 前者评疗效，后者评诊断概率，两套类别不可互换 |
| cTACE（碘油+化疗药） | DEB-TACE（载药微球） | 栓塞机制、剂量学与并发症谱不同 |
| TAE（单纯栓塞） | TACE | 是否含化疗药物直接影响适应证与毒性 |
| Vp3（一级分支癌栓） | Vp4（主干癌栓） | 决定 TACE 是相对禁忌还是绝对禁忌 |
| REILD（放射性栓塞后肝病） | 普通肝衰竭 / 病毒性肝炎发作 | 诊断标准与时间窗特异（Y90 后数周至数月） |
| 放射性肺炎 | 放射性肝炎 / REILD | 不同靶器官、不同限值、不同预防手段 |
| Child-Pugh 分级 | ALBI 分级 / MELD | 三套体系阈值与用途不同，不可互相替代 |
| BCLC 分期 | CNLC 分期 | 两套分期对同一患者的归类可能不同，混用会导致适应证判断错 |
| 玻璃微球（TheraSphere） | 树脂微球（SIR-Spheres） | 剂量学体系不通用：前者用 Gy 处方，后者用 BSA/经验法 |
| GBq | mCi | 1 GBq = 27 mCi，混用导致 27 倍剂量错误 |
| Gy | cGy | 100 倍差 |
| HAIC（肝动脉灌注化疗） | 全身静脉化疗 | 给药途径决定毒性谱与适应证 |
| 门静脉癌栓（PVTT，肿瘤性） | 门静脉血栓（bland thrombus） | 处理策略完全不同，影像鉴别要点不同 |
| 肺分流率（LSF） | 肺灌注比例 / 分流分数（心内分流） | 概念不同 |
| Vp2（二级分支/段支） | Vp3 | 日本分型：段支 = Vp2，一级分支（门脉左/右支）= Vp3，主干 = Vp4。混用会导致禁忌判断错一级 |
| Vp3（一级分支/叶支） | Vp4 | 同上；Vp4 的 Y90 禁忌是**条件性**的（需同时 MAA 显像癌栓无摄取） |
| 程氏 Ⅱ 型 | Vp3 | 中国分型对照：程 Ⅰ ≈ Vp1–2，程 Ⅱ ≈ Vp3，程 Ⅲ ≈ Vp4，程 Ⅳ 累及肠系膜上静脉 |
| REILD（放射性栓塞后肝病） | 外照射经典 RILD | REILD 为**有黄疸**型；经典外照射 RILD 为**无黄疸**型腹水，两者机制与时间窗不同 |
| mRECIST | LI-RADS TRA v2024 | v2024 起放射路径为独立算法，与 mRECIST **并行**而非替代；且 LR-TR v2024 不适用于系统/免疫治疗 |
| 120 ± 20 Gy（玻璃标准处方） | ≥205 Gy（个体化靶剂量） | 两个口径对应不同治疗意图（标准 vs 个体化/消融性），混用会导致剂量目标错档 |

### 2.2 排他性措辞词典（E5）

`必须`、`唯一`、`绝对`、`一定`、`只能`、`毫无疑问`、`无需考虑`、`必然`、`任何情况下`、`标准答案就是`、`肯定不能`、`不允许`、`完全排除`

**豁免规则**（见 rubric D4）：当排他措辞指向题库 `unacceptable` 反向确认的**真禁忌**时不计入。豁免必须在评分备注写明豁免了哪一句；**默认不豁免**。

### 2.3 模糊/对冲措辞词典（E6）

`可能`、`或许`、`也许`、`视情况`、`存在争议`、`尚无定论`、`需个体化`、`证据有限`、`不一定`、`有待研究`、`尚在探索`

**E6 的判定不是数密度**，而是看它是否落在"本题有唯一正确答案"的要点上。因此 E6 只能是 `flag_for_review`——规则层能算出模糊词密度，但**无法判断某个具体争议点是否真有唯一答案**，那需要题库的 `must_have` 标注与人工裁定。

### 2.6 免责声明与科普冗余句库（E8）

**疾病科普段落线索句**：

`是人体`、`是最大的`、`是常见的恶性肿瘤`、`发病率`、`流行病学`、`其发病与`、`早期常无明显症状`、`早期常无症状`、`解剖上`、`组织学上`、`随着病情进展可出现`、`诊断依赖影像学`、`是一种常见的`、`在全球范围内`

**E8 的判定是占比而非计数**：`redundancy_ratio = 免责声明+疾病科普段落字数 / 全文字数 ≥ 0.25`。只出现一句结尾免责是正常且合理的，不该罚；占据大段篇幅挤掉决策信息才该罚。

### 2.7 引用白名单（E3）

来源：题库各题 `reference_basis` 的并集 + 一份公开的肝胆介入核心文献清单（指南名、经典试验名、`NCT\d{8}`、PMID）。

抽取正则：
- `《[^》]{2,60}》`（中文指南/共识名）
- `\bNCT\d{8}\b`
- `\bPMID[:\s]?\d{6,9}\b`
- `\b\d{4}\s*年?\s*(?:发表|报道|研究)`
- `[A-Z][a-z]+\s+et\s+al\.?`

**E3 永远只能是 `flag_for_review`**。理由：白名单不可能穷尽所有真实文献，误报率无法压到 0。结果里必须分别报告"确认幻觉数"与"无法裁定数"——**把这两个数混在一起报，就是在用不确定性制造虚假的确定性。**

白名单的静态部分（`CORE_REFERENCES`）只收录**本仓库文档中已核实过的来源名**（§2.4 核实依据列、交接说明纠错表、deviation_log），不新增任何仓库外文献——凭空编一个"白名单条目"与凭空编一个引文，是同一种幻觉。

### 2.8 规则层辅助词典（守卫与可观测代理）

§2.1–§2.7 定义"什么算错"，本节定义"什么情况下不许判错"。它们同样是词典、同样必须可 review，因为**每一条守卫都对应一类实测到的假阳性**。缺了它们，规则层在零缺陷回答上的 `confirmed` 数不为 0，整个阳性对照验收（§5）直接失败。

#### 2.8.1 三条由实测驱动的必要收紧

| # | 朴素规则 | 实测假阳性 | 收紧后 |
|---|---|---|---|
| 1 | 排他措辞计数 ≥2 → E5 confirmed | 20 份零缺陷回答中 **14 份** 命中 ≥2；「绝对」出现 15 次，**15 次全部**是「绝对禁忌」这一正确术语 | 计数前先扣除 `排他措辞豁免` 搭配；且必须同时满足「争议双向呈现缺席」才 confirmed |
| 2 | 术语对同句共现 → E1b confirmed | 「不要用 RECIST 1.1，应改用 mRECIST」是**正确**表述却同时含两个术语 | 仅当同句共现 **且** 出现 `术语替换标记` 才 confirmed，否则降为 flag |
| 3 | 前 3 句无术式名 → E7 confirmed | 20 份零缺陷回答中 **7 份** 命中，且全是剂量计算题（提问本身就不含术式名） | 双条件：前 3 句既无题干核心实体、**又**无任何 `结论标记`，才 confirmed |

> 这三条不是"把规则调松以让测试通过"。它们是同一个方法学要点：**`confirmed` 的资格来自假阳性率，而假阳性率只能靠阳性对照 + 阴性对照一起测出来**。只有缺陷注入（阳性）没有零缺陷对照（阴性），规则层会朝着"什么都报"的方向退化，而这种退化在只看 recall 时完全隐形。

#### 2.8.2 守卫词典

**术语替换标记**（E1b 升级为 confirmed 的必要条件）：

`即是`、`即为`、`也就是`、`等同于`、`相当于`、`等于`、`又称`、`也叫`、`可互换`、`同义`、`视为`、`算作`、`换成`、`替换为`、`就是一样`、`两者相同`、`通用`

> 刻意不收单字「即」：它会命中「必须立即停用」「即使」这类与术语替换无关的常见搭配，单字标记在中文里假阳性率高到不可用。

**排他措辞豁免**（E5 计数前扣除；均为正确临床术语而非过度自信）：

`绝对禁忌`、`绝对禁忌证`、`绝对不应`、`绝对不可`、`绝对禁用`、`必须排除`、`必须停用`、`必须停药`、`必须纠正`、`必须先`、`必须立即停`、`必然进展`、`唯一可根治`、`唯一治愈`

> 此外，E1c 与 E2d 共用 `禁止性框架` 守卫：回答在「必须优先排除的安全项」下**逐字引用**一条错误断言以便否定它，是正确写法，不是犯错。

**近距否定前缀**（E2d：在 forbid 型 hint 命中处**之前 4 字内**出现即视为被否定）：

| ALT | 谷丙转氨酶 / 丙氨酸氨基转移酶 / ALT | U/L | — | `ALT_U_L` | |
| ALP | 碱性磷酸酶 / ALP | U/L | — | `ALP_U_L`, `ALP_baseline_U_L` | |
| CRP | C反应蛋白 / C 反应蛋白 / CRP | mg/L | — | `CRP_mg_L` | |
| PT | 凝血酶原时间 / PT | s | — | `PT_prolong_s` | **只 flag 不 confirmed**：vignette 记的是"延长秒数"，回答里常写"绝对秒数"，两者不可直接比 |

> `baseline` 字段必须一并计入允许值集合：治疗后复查题（如 SIRT-015、SIRT-016、TACE-006）的正确答案必然同时引用基线与当前两个值，只比当前值会把正确答案判成虚构。
>
> 允许值集合 = `vignette.labs` 的结构化值 ∪ **`stem` 散文里正则抽出的值**。实测 20 题中有 10 题的 `stem` 含检验值，而其中 SIRT-004、COMBO-003 的 `vignette.labs` 为空——只比结构化字段，这两题的正确答案会被全数误判。

## 3. 错误实例的记录格式

`data/scores/error_instances.jsonl`，一行一个错误实例：

```json
{
  "qid": "SIRT-007",
  "response_id": "R0023",
  "model": "（揭盲后填入）",
  "code": "E12",
  "layer": "rule",
  "verdict": "confirmed",
  "evidence": "回答称『患者肌酐 210 μmol/L，属肾功能不全』，而 vignette 中 Cr = 78 μmol/L",
  "char_span": [412, 448],
  "dimension_impact": ["D1", "D2"],
  "rater_note": "典型的虚构题干信息，推理链本身自洽，只有逐字段比对能抓到",
  "ts": "2026-10-06T21:14+08:00"
}
```

`evidence` 与 `char_span` 是强制字段。**没有原文证据的错误标注不算数**——这条约束同样适用于 LLM-judge 的输出，judge prompt 里要求它必须引用片段，否则该条判定丢弃。

**`span_kind` 是必须区分的补充字段**（2026-10-07 加入）：取值 `match` 或 `omission`。漏报型错误（E2a/E2b/E4b）在回答里**没有**对应文本，`char_span` 只能是 `[0,0]`。若不显式标出，下游会把 `[0,0]` 当成"位于回答开头的证据"——这是会静默传播的脏数据，且在做错误定位热力图时会把所有漏报堆到字符 0 处。规则层与 judge 层输出均须带此字段。

`rule_version` 记录产出该条 finding 的规则层版本，便于词典更新后区分新旧结果。

## 4. 清单外观察的回收流程

1. 阶段 3 从 `human_pass1.csv` 抽出全部非"无"的 `off_list_observation`。
2. 按语义归并（人工，约 20 分钟），统计每类出现频次。
3. 频次 ≥ 3 的新类型 → 追加为 `E13+`，写清操作性定义、检测层、可自动检测线索。
4. 频次 1–2 的 → 记入 `docs/error_taxonomy.md` 附录"候选类型（证据不足）"，不进入正式分类。
5. taxonomy 版本号 +0.1，并在 README 说明"v1.0 → v1.1 新增了哪些类型、由多少条清单外观察驱动"。

> **这个流程本身就是 JD 职责②「从个案归纳出共性问题与优化方向」的直接实现**，面试时应当作为一条独立的方法论点来讲，而不是一句"我还整理了一些其他错误"。

## 5. 阳性对照验收门（`python src/rule_check.py --self-test`）

一个从不在已知错误上报警的检测器，和一个从不报警的检测器，看起来一模一样。所以规则层每次改动后都必须同时跑**两种**对照，缺一种都不算通过：

| 对照 | 数据 | 验收标准 | 只跑这一种会怎样 |
|---|---|---|---|
| **阳性** | `mock_defective`（20 份，注入 59 个已知缺陷，真值在 `mock_ground_truth.jsonl`） | 每类被注入的错误码 **recall > 0** | 检测线索写错时无人发现 |
| **阴性** | `mock_clean`（20 份，零缺陷） | **confirmed 数必须 = 0** | 规则层朝"什么都报"退化，而这种退化在只看 recall 时完全隐形 |

另有两条结构性检查：

3. **越权升级检查**：§1 规定只能 `flag_for_review` 的错误码（E1a/E1c/E3/E4b/E6/E10），代码不得输出 `confirmed`。`CODE_MAX_VERDICT` 是这条约束的可执行形式，违反即验收失败。
4. **无阳性对照的错误码必须显式列出**：当前 `mock_models.py` 只注入 E1a/E2a/E5/E7/E8/E12 六类，因此 E1b/E1c/E3/E4b/E6/E9/E10/E11 **只能测假阳性率、不能测 recall**。自检会打印这份清单——把"没测"说成"通过"是本文件最不允许的事。要补，就去 `mock_models.py` 加注入器，不能靠声称。

**两级 recall 分开报**：

- **代码级**：注入了 E5，规则层是否产出过至少一条 E5？
- **证据级**：注入的那段具体文本，是否落在某条 E5 finding 的 `char_span` 附近？

只报代码级会高估检测能力——规则层可能因为**另一个**原因在同一份回答上报了同一个码。

> **失败时的处置**：修 `dictionaries.py` 的检测线索或守卫，**不要改验收标准**。如果反复出现同一类假阳性，那是词典的 bug；如果反复出现同一类漏报，那是 `detection_hint` 写得不够——回去补题库，也不是放松阈值。
