# 回答取回提示词包（answer wrapper）

**用途**：5 个模型逐字相同地提问，手动取回回答。
**核心原则**：**提示词不对称是最容易被忽略、也最致命的偏差来源**。任何"因为 Claude 喜欢分点所以多写一句"的临时调整，都会让模型间比较失去意义。

---

## 1. 取回前的一次性设置（每个模型都做一遍）

| 项 | 设置 | 理由 |
|---|---|---|
| 对话历史 | **每道题新开一个对话** | 跨题上下文会泄漏，且不同模型的上下文长度不同 |
| 自定义指令 / System prompt / 记忆功能 | **全部清空或关闭** | 否则你账号里的历史偏好会不对称地影响某个模型 |
| 联网搜索 | **关闭** | 各模型搜索能力差异极大，开着等于在比"谁的搜索好"而不是"谁的知识与推理好"。我们要测的是参数化知识 |
| 深度思考 / 推理模式 | **保持该产品的默认状态**，不要手动开关 | 默认状态 = 普通用户拿到的东西，这是生态效度最高的口径。**在 meta 里如实记录当时是开还是关** |
| temperature / top_p | 网页版通常不可控 | 不可控就在 `meta.json` 里写 `"temperature": "不可控（网页版）"`，README 如实声明 |

> **为什么不做角色设定**（如"你是一位介入放射科主任医师"）：角色启动会系统性抬高输出质量，且对不同模型的抬升幅度不同。我们要测的是**模型面对临床问题时的默认行为**——这才是"定位模型短板"想知道的东西。角色启动的影响作为已识别的混杂因素写进 README，不做也不假装做过。

---

## 2. 主提问模板（逐字复制，禁止改动任何一个字）

把下面整块粘进对话框，`{stem}` 与 `{question}` 由 `src/blind_shuffle.py --emit-prompts` 自动填充，你不需要手动拼：

```text
以下是一份用于医学教育与大模型评测的去标识化教学病例。

【病例】
{stem}

【提问】
{question}

请依据上述信息给出你的处理建议与理由。
```

### 2.1 一个刻意的取舍，以及它的代价

模板里**没有**写"如果信息不足请指出缺什么"。

- **为什么不写**：`gap_declared` 是 D4（不确定性表达）的核心中间量。一旦在提示词里要求模型声明信息缺口，就等于把答案告诉它，D4 的区分度直接归零。
- **代价**：某些模型可能不回答案例、只反问一堆澄清问题。
- **处理规则（写进 protocol，不可临场改）**：这种回答按 `off_target = true` 记 **D5 = 0**，其余维度按"实际给出的内容"评（若完全没给临床内容，D1–D4 记 0 并在 `rater_note` 写 `refused_to_answer`）。**这本身就是一个有价值的评测发现**——"在高风险临床问题上倾向于反问而非给出可评估的答案"是产品层面的真实缺陷。

## 3. 格式敏感性分析模板（6 题子集 × 5 模型 = 30 次额外取回）

用于回答"模型排序会不会随提问格式而改变"。**与主集分开存放、分开统计，不与主集混合。**

```text
以下是一份用于医学教育与大模型评测的去标识化教学病例。

【病例】
{stem}

【提问】
{question}

请用不超过 300 字回答，先给结论，再给理由。
```

统计时看两件事：① 各模型 D5 是否普遍上升（格式约束是否弥补了自我组织能力差异）；② **模型间排序是否发生翻转**。若翻转，说明主集的结论对提问格式敏感，必须在 README 里降级表述。

---

## 4. 取回 SOP（每份回答约 20–30 秒）

1. 新开对话 → 粘贴 → 发送。
2. **等模型完全停止输出**再复制。
3. **复制全文，一个字都不要删**。特别是：
   - 开头的"作为 AI 助手…"、结尾的"请务必咨询专业医生"——**这些免责声明正是 E8（安全冗余）与 D5 的 `redundancy_ratio` 的检测对象**，删掉就等于销毁证据。
   - Markdown 格式符号（`#`、`*`、表格线）——D5 的结构判断依赖它们。
4. 若回答被长度限制截断：**记录 `truncated = true`，不要点"继续生成"**。续写会改变长度分布，使长度偏置的调整失效。截断样本在统计时单独标注。
5. 打开 `tools/paste_recorder.html`，粘贴文本，填 4 个元数据字段，点保存。全部取完后一键导出 `responses.jsonl` 到 `data/responses/raw/`。

### 4.1 必须记录的元数据（`meta.json` / `responses.jsonl` 每行）

| 字段 | 例 | 为什么必须记 |
|---|---|---|
| `qid` | `SIRT-007` | 主键 |
| `model` | `deepseek` | 内部用；取回阶段可见，揭盲后对评分者不可见 |
| `model_version` | 界面**真实显示**的版本号；不显示则填 `未公开显示（以取回日期标识）` | **版本漂移**：结论对模型版本敏感，不记就无法复现。但**填进去的必须是观测值**——不得把文档示例中的型号名当版本号抄，那是伪造元数据。版本号不可得时，靠"同一模型 26 项一次连续取完"保证版本恒定 |
| `retrieved_at` | `2026-10-04T15:20+08:00` | 同上；也用于检查是否都在 48 小时内取完。版本号不可得时，它就是版本标识 |
| `mode` | `深度思考=默认开(未改动) / 联网=手动关` | 各产品默认状态不同，必须留痕。**开/关按实测填，不要照抄本行示例**；版本号黑箱的产品，这一项是唯一标识信息，不可留空 |
| `truncated` | `false` | 见 §4.4 |
| `char_count` | `2841` | 长度偏置调整的协变量（由脚本自动算，不用手填） |
| `prompt_variant` | `main` / `format_probe` | 两个集合必须分开 |

## 5. 取回进度自查（做完对一遍）

| 集合 | 应有份数 | 算法 |
|---|---|---|
| 主集 · 核心面板 | 60 | 3 模型（DeepSeek / GPT-5 / Claude）× 20 题 |
| 主集 · 扩展面板 | 40 | 2 模型（Qwen3 / Kimi）× 20 题 |
| 格式探针 | 30 | 5 模型 × 6 题 |
| **合计** | **130** | |

`src/blind_shuffle.py` 在匿名化时会检查缺漏并打印 `[WARN] 缺 N 份回答`，不用手工数。

## 6. judge 提示词（见 `prompts/judge_pointwise.md` 与 `judge_pairwise.md`）

judge 模型必须是**被评面板之外的第 6 个模型**（Gemini / GLM / 豆包任一，取回时确定具体型号并写入 meta）。理由与残余风险见 `docs/_stage0_review.md` §3 第 3 条：

- judge 若与被评模型同源，会系统性偏爱与自己风格相似的输出（self-preference bias）。
- 用面板外模型后，残余风险是它仍可能有训练语料带来的风格偏好（例如偏爱英文式结构化表达）——这一条写进 README，不假装消除。

judge 的 pointwise 与 pairwise 两套 prompt 分开跑：
- **pointwise**（100 次）：对每份回答按 6 个维度独立打分，用于与人工分数算一致性（α / weighted κ）。
- **pairwise**（120 次 = 3 对模型 × 20 题 × 2 种顺序）：A/B 互换，**只有两次同向才计入胜率，反向记 tie 并单独报告"位置敏感对数"**。那个数字本身就是 judge 可靠性的证据。
