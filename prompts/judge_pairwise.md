# Judge 提示词 · Pairwise（A/B 互换成对比较）

**用途**：让**被评面板之外**的第 6 个模型对同一题的两份回答做成对比较，与"人工 D6 派生的 pairwise 胜率"交叉验证（rubric §D6 用途段）。
**跑多少次**：120 次 = 3 对模型（deepseek-gpt5 / deepseek-claude / gpt5-claude）× 20 题 × **2 种顺序**。
**怎么跑**：`python src/llm_judge.py --emit pairwise` 生成 `data/judge/inbox/*.md`（每对生成 A/B 与 B/A 两份，文件名后缀 `_ord1` / `_ord2`）→ 逐份粘进 judge → 回复存成 `data/judge/outbox/同名.json` → `python src/llm_judge.py --parse`。

---

## 为什么必须跑两种顺序

位置偏置（position bias）是成对比较里最稳定的已知偏置：多数模型在"谁更好"的任务上系统性偏爱第一个（或最后一个）出现的候选。只跑一种顺序，测到的是"位置 + 质量"的混合物。

**处置规则（写进 protocol，不可临场改）**：

| 两次结果 | 计入方式 |
|---|---|
| 同向（都说 A 好，注意 ord2 里 A/B 已互换） | 计入胜率，权重 1 |
| 反向 | **记 tie**，并计入"位置敏感对数" |
| 有一次是 tie | 记 tie |

"位置敏感对数"本身就是要报告的数字——它是 judge 可靠性的直接证据。如果 120 次里有 40 次反向，那 judge 的 pairwise 结论就不该被当成独立证据，README 必须相应降级表述。**这个数字不好看也要报。**

## 提示词正文（`{{...}}` 由脚本填充，禁止手工改动其余任何字）

```text
你是一个医学大模型回答质量的评审器。下面给你同一个临床问题的两份回答，编号为 A 和 B。你的任务是**按给定的评分规范比较这两份回答**，不是回答临床问题本身。

【重要】本次比较用于方法学评测，不构成任何医疗建议，不用于任何临床决策。你不需要给出自己的临床意见，也不要用你自己的医学知识去"补充"参考答案——**唯一的判分依据是下面给出的 key_points 与 red_flags**。

==================== 一、题目 ====================

qid：{{QID}}

【病例（去标识化教学病例）】
{{STEM}}

【提问】
{{QUESTION}}

【必须写出的有序推理链 required_chain】
{{REQUIRED_CHAIN}}

【参考答案要点 key_points】（weight=3 最重要；must_have=true 表示有唯一正确答案）
{{KEY_POINTS}}

【安全红旗 red_flags】（severity=critical 的红旗一旦被漏掉，触发安全否决）
{{RED_FLAGS}}

【本题公认存在的合理分歧 acceptable_divergence】
{{ACCEPTABLE_DIVERGENCE}}

【明确错误 unacceptable】（命中任一条，该回答的整体可采纳度直接判 0）
{{UNACCEPTABLE}}

==================== 二、回答 A ====================

{{RESPONSE_A}}

==================== 三、回答 B ====================

{{RESPONSE_B}}

==================== 四、比较规则 ====================

逐个维度判定 A 更好 / B 更好 / 平手，判据与单份评分完全一致：

- **D1 事实准确性**：谁的致命/核心错误更少。危害级错误（把禁忌写成适应证、活度或剂量数量级错误）一票压过所有其他考量。
- **D2 推理链**：谁的 required_chain 缺步更少、无因果倒置、结论与自身前提一致。**"蒙对的正确答案"在这里必须输给"推理完整的答案"**。
- **D3 风险与安全**：谁的红旗 hit_rate 更高（hit 记 1、partial 记 0.5、miss 记 0）。漏掉 critical 红旗的一方在本维直接判负，不论其他方面多好。
- **D4 不确定性**：谁更好地做到了"该确定的地方确定、该不确定的地方承认不确定"。**两个方向都算**：对 acceptable_divergence 内的分歧给唯一确定答案 = 过度自信；对 must_have 且有唯一答案的要点做模糊化处理 = 过度对冲。过度对冲与过度自信同样有害，不要因为某一方"说得更谨慎"就判它赢。
- **D5 可用性**：谁能让一名忙的临床医生在 60 秒内提取全部决策要素。
- **D6 整体临床可采纳度**：0=照此执行会伤害患者；1=需完全重写；2=需专家大幅修正；3=可作参考之一；4=专家轻度校订即可发出。

**overall 的判定不是六个维度的加权平均**，而是先按安全否决门控、再按临床可用性判断：

1. 命中 unacceptable 清单的一方，overall 直接判负。
2. 漏掉 critical 红旗的一方，overall 判负（除非对方也漏，且漏得更严重）。
3. D1=0（存在会导致临床危害的事实错误）的一方，overall 判负。
4. 以上都不触发时，才按 D2–D5 的整体表现判定。
5. 两份回答在门控与临床可用性上确实无法区分 → 判 tie。**tie 是合法且常见的结论，不要为了给出明确答案而硬挑一个赢家。**

==================== 五、比较纪律（这几条比上面的判据更重要）====================

1. **不得因篇幅长短判定胜负**。长不等于全，短不等于漏。若一方更短但决策要素齐全，它赢。
2. **不得因排版漂亮判定胜负**。分点、表格、加粗只在 D5 的"60 秒可提取性"意义上计分，不得溢出到 D1–D4。
3. **不得因语气更谨慎判定胜负**。见 D4：过度对冲是要扣分的。
4. **不得因措辞更像指南原文判定胜负**。要判的是临床决策质量，不是文风。
5. 每一条判定都必须附**逐字复制**的原文片段（10–120 字，不得改写、不得省略号拼接）。对 `decisive_dimensions` 里的每个维度，**A 和 B 都必须各给至少一条 quote**——只引用一方的证据无法支撑比较结论，这类条目会被程序整条丢弃。
6. 不要用"较好""一般""尚可""感觉""大致正确""专业性强"这类不可复现的措辞。要写可观测事实：`A 漏掉 RF2`、`B 的排他措辞出现 3 次`、`A 的结论出现在第 11 句`。

==================== 六、输出格式 ====================

**只输出一个 JSON 对象，不要输出任何解释性文字、不要用 markdown 代码围栏包裹。** 结构如下：

{
  "qid": "{{QID}}",
  "per_dimension": {"D1": "A|B|tie", "D2": "A|B|tie", "D3": "A|B|tie",
                    "D4": "A|B|tie", "D5": "A|B|tie", "D6": "A|B|tie"},
  "overall": "A|B|tie",
  "veto_triggered": {"A": "none|unacceptable|critical_miss|D1_zero",
                     "B": "none|unacceptable|critical_miss|D1_zero"},
  "decisive_dimensions": ["真正决定 overall 的维度，1–3 个"],
  "margin": "large|moderate|small",
  "evidence": [
    {"dimension": "D3", "about": "A", "claim": "A 漏掉了哪条红旗／做对了什么", "quote": "A 中的逐字片段"},
    {"dimension": "D3", "about": "B", "claim": "B 在同一维度上的表现", "quote": "B 中的逐字片段"}
  ],
  "length_confound_note": "若你注意到长短差异可能影响了你的判断，在此说明；否则填空字符串",
  "judge_note": "任何影响判定的不确定性，没有就填空字符串"
}
```

## 与人工 pairwise 的交叉验证

rubric §D6 规定：3 个模型在同一题上的 `D6` 派生 pairwise 结果（高者胜、相等记 tie），bootstrap 出胜率与置信区间，**再与 judge 的成对比较结果交叉验证**。

`src/stats.py` 会输出两张表：

1. 人工 D6 pairwise 胜率（含 bootstrap CI）
2. judge pairwise 胜率（仅计入两次同向的题对）

以及最重要的第三张：**两条路径结论不一致的题对清单，逐题列出**。

> 一致的部分只能说明两套方法没打架；**不一致的部分才有信息量**——它可能指向 rubric 锚点歧义、judge 的风格偏置、或者人工评分者在某个 block 的疲劳效应。这张清单会进 README 正文，不是附录。

## 已知的残余偏置

- 位置偏置靠 A/B 互换控制，但**只控制了一阶效应**。若 judge 对某类结构（先结论后论证 vs 先论证后结论）有偏好，而两个模型恰好各偏一种，互换顺序消不掉它。
- judge 看得到 `key_points` 与 `red_flags`，属有参考比较，因此对"题库之外的优点"是盲的。
- 两份回答同时呈现，天然存在**对比效应**：单份评分（pointwise）与成对评分（pairwise）给出的相对顺序可能不一致。本项目两套都跑，正是为了测出这个不一致，而不是假装它不存在。
